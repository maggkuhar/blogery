*Папка:* `/root/трафик`
*Порт:* 5000
*Сервис:* `blogery.service`
*GitHub:* `maggkuhar/trafik`
*Мета-папка в Ядре:* `/root/yadro/проекты/внешний-трафик/`

## Суть проекта

CRM-система для работы с блогерами, тематическими группами и каналами в соцсетях (поиск, переговоры, шаблоны, статистика сотрудничества). Внутри той же платформы живёт **SMM-блок** — публикация контента, постинг, медиатека. SMM продаётся как отдельный продукт; CRM-блогеры — внутренний инструмент.

## Архитектура / стек

- **Backend:** Flask + blueprints (один блок = один blueprint в одноимённой папке)
- **БД:** SQLite (`blogery.db`) — все таблицы в одной базе
- **Точка входа:** `app.py` — только Flask app + `register_blueprints`
- **Общий код:** `database.py` (`get_db`, `init_db`), `constants.py` (PLATFORMS, STATUSES)
- **Шеред-шаблоны:** `templates/_nav.html` (навигация), `templates/form.html` (форма блогеры/группы/каналы)
- **Платформы:** Instagram, ВКонтакте, TikTok, YouTube (плюс Одноклассники)

## Ключевые решения

- **Один блок = один Flask blueprint = одна папка.** `app.py` — только склейка. Не пихать роуты в `app.py` или общую папку. Архитектурное правило проекта.
- **Инстаграм/TikTok боты — на отдельных аккаунтах**, не на основных пользовательских. Создаются специально под бота. Никогда не использовать аккаунты пользователя.
- **Авто-поиск блогеров — только официальные API там, где есть** (VK API, YouTube/Google API). Для Instagram и TikTok — бот-аккаунты как пользователи (парсинг как реальный человек).
- **Архитектура ботов: «разведчик + контакт».** Один бот = один аккаунт = одна соцсеть. Разведчик (Scout) только смотрит/собирает данные — почти не палится. Контакт — лайки/комменты/подписки/сообщения по лимитам. Без ограничения количества ботов — сколько надо, столько подключаем.
- **Каждый бот — индивидуальные настройки** в панели: лимиты, задержки, расписание, история банов. При бане — фиксируем причину, заводим нового бота с учётом ошибок, систему не меняем.
- **SMM-платформа — этапная разработка.** Этап 1 (хранение аккаунтов + ручная публикация) — готов. Дальше: автопостинг → AI-генерация (текст/картинки/видео/музыка) → мультипользователь.
- **Порядок разработки CRM:** сначала каркас (БД + веб-панель) → потом автопоиск по платформам → потом AI-анализ и шаблоны.
